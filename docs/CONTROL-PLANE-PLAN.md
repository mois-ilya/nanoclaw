# План: управляемый агент (возможности, коннекторы, ключи, контекст)

Статус: план v3 (упрощённый), 2026-10-10. Основан на ревью кода (контекст, MCP/self-mod, секреты/изоляция, мини-апп), обзоре практик
(Anthropic, MCP spec 2026-07-28, Hermes Agent), независимом проекте Codex и его критике первой версии этого плана.

## 1. Цель

Агент, у которого всё, что он умеет и к чему имеет доступ, — видимая сущность с включателем, происхождением и ценой в контексте.
Управление из двух мест, которые всегда показывают одно и то же: чат (намерение: «подключи почту», «выключи календарь») и Кабинет (пульт).
Ключи агент не видит никогда. Опасные действия подтверждаются кнопкой, которую рисует хост, а не модель.

## 2. Где мы сейчас: главное из ревью

Хорошо сделано: ключ Anthropic только в nanogate (агент держит сессионный токен), серверные секреты через sops → LoadCredential,
изоляция тенантов (отдельные папки, сети сессий, токены nanogate), детерминированная сборка CLAUDE.md на хосте, карточки одобрения self-mod
с редактированием и защитой от подмены, общий путь решений чат ↔ Кабинет для заявок друзей (`decisions.ts`).

Проблемы, отсортированные по важности:

Полезное, что уже есть и пригодится: шифрованная таблица `secrets` по тенантам в nanogate (никем не читается), шов шлюза с одобрениями
запросов (`gateway-approval-coordinator.ts`, у nanogate заглушка), вспомогательные контейнеры сессии в podman-драйвере (как nanorelay),
`requestApproval` + карточки `q:`, паттерн «агент предлагает — владелец завершает в Кабинете» (`ncl guest append`).
SDK 0.3.280 уже умеет: `tools`, `skills`, `strictMcpConfig`, `excludeDynamicSections`, `alwaysLoad`, per-server `timeout`,
программные хуки (включая `SessionStart`), `mcpServerStatus()/setMcpServers()/toggleMcpServer()`.

## 3. Принцип: «хорошо работает», а не «крепость»

Делаем то, что даёт пользу сейчас, и не строим общих механизмов под будущие случаи. Признаки оверинжиниринга, которые мы вычеркнули
из v2: единая таблица всех возможностей с версиями и дайджестами, четыре уровня областей (сервер/пользователь/агент/топик), резолвер
с миграцией и откатом, асинхронные подтверждения с одноразовым claim, карантинный опрос внешних MCP, taint-флаги, сборка образов
для самописных MCP. Всё это возвращается, только если появится реальная нужда.

## 4. Целевая картина (минимальная)

- **Ключи.** Серверные — как сейчас (sops). Пользовательские — только запись из Кабинета в существующую таблицу `secrets` nanogate.
  Агент ключей не видит: в конфиге коннектора лежит имя ключа, значение подставляет nanogate.
- **Коннекторы = удалённые MCP по HTTPS** (GitHub, Gmail, позже HA и др.). Агент ходит к ним через nanogate
  (`http://nanorelay:8081/mcp/<id>`), nanogate проверяет, что коннектор принадлежит тенанту и включён, подставляет ключ и проксирует.
  Свои stdio-серверы и самописный код пока не поддерживаем (это и есть дорогая часть).
- **Подтверждение** — список «опасных» инструментов коннектора (по умолчанию все, кроме чтения). nanogate держит вызов, хост шлёт
  карточку с кнопками в чат, ждём до 5 минут, иначе отказ. Таймаут MCP у агента выставляем чуть больше.
- **Контекст.** Описания инструментов коннекторов грузятся по требованию (tool search), встроенные инструменты и навыки — явным списком,
  промпт без противоречий и лишнего.
- **Кабинет.** Экран «Коннекторы» (каталог, ключ, вкл/выкл, опасные инструменты, последние вызовы), навыки с настоящим включателем,
  в «Инструкциях» — размер каждого слоя в токенах.

## 5. Этапы

### Этап 0 — Порядок и экономия
1. Убрать HA из Кабинета, API, промпта и папки агента (не используется).
2. `add_mcp_server`: без значений в `env`/`headers` и только HTTPS; `ncl groups config add/remove-mcp-server` — только для хоста.
3. `strictMcpConfig: true`, явные `tools` и `skills`; не регистрировать `install_packages` на Podman и self-mod/`create_agent` у друзей.
4. Tool search через nanogate (`ENABLE_TOOL_SEARCH`, beta, валидатор инструментов) и кеш 1 ч — включаем, если проверка на живом
   контейнере проходит; замер контекста до/после.
5. Промпт: убрать противоречия и дубли, друзьям — только их доки.
6. Лимит расходов на окно для владельца (`perTurnCapMicros`).
7. Мелочи Кабинета: бейдж подключения, мёртвый UI Tailscale-ключа, показ причин 403, `gateIdOf` для коннектора.

### Этап 1 — Коннекторы через nanogate, первый — GitHub
1. nanogate: эндпоинт `/mcp/<id>` (проверка сессии и тенанта, подстановка ключа, журнал вызовов), третий порт nanorelay,
   исключение в валидации для этого внутреннего адреса.
2. Хост: таблица коннекторов (id, тенант, url, имя ключа, опасные инструменты, enabled), запись в `container.json` агента.
   Изменения применяются ко всем сессиям агента (перезапуск в простое).
3. Подтверждение опасных вызовов карточкой в чат (синхронно, до 5 минут).
4. Кабинет: экран «Коннекторы», поле ключа «Мой»; навыки с включателем.
5. GitHub: официальный удалённый MCP + персональный токен.
6. Groq: опция «свой ключ» у пользователя (общий остаётся по умолчанию).

### Этап 2 — Почта и подключение по просьбе
1. OAuth на хосте (callback на домене Кабинета, токены в `secrets`, обновление на сервере).
2. Gmail: официальный MCP через Google Cloud владельца (чтение и черновики), календарь тем же OAuth.
3. «Подключи вот этот MCP»: агент присылает ссылку → карточка с кнопками → после одобрения коннектор в Кабинете.
4. Промпт на английском + русская копия для Кабинета.

### Потом, если понадобится
IMAP через свой сервер (нужны воркеры для stdio), самописные MCP, HA, коннекторы для друзей, возможности по топикам, память с историей
изменений, экран «Что сейчас происходит».

## 6. Решения владельца (2026-10-10)

Брокер — в nanogate. Почта — Gmail MCP через Google Cloud владельца, IMAP — опция позже. Egress владельца — открытый веб.
Groq — общий по умолчанию, свой ключ — опция. HA не используется.

## 7. Сознательно не закрываем

- Агент с открытым вебом может унести то, что прочитал (не ключи). Смягчение — подтверждение опасных вызовов коннекторов.
- Встроенные Bash/WebFetch не подтверждаются кнопкой.
- Инструкции и хуки через файлы настроек агента (`settingSources`) — не трогаем, пока не мешает.
- Память агента может хранить внедрённые инструкции.
